## Starting defaults

These defaults make the local plan concrete without claiming that open commercial/provider questions are settled:

- Use a single Next.js/TypeScript application with server-only domain modules and a separate worker entry point later; PostgreSQL/Prisma for persistence.
- Use npm and its lockfile unless the implementation workspace already has a package-manager convention. Select supported runtime/framework versions during S1; record exact versions after validation.
- Use Tailwind CSS for the initial dashboard and Firebase Auth as the proposed managed-auth adapter. Real Firebase project setup belongs to S2; a development fake identity, if needed for tests, must be inaccessible in production.
- Use local/disposable PostgreSQL for integration tests. Decide the actual database provisioning method from available tools at implementation time; no hosted database is required to write the initial shell.
- Keep Gemini, Meta outbound, and real-data AI processing disabled initially as in [.env.example](../.env.example).
- Treat plan prices, provider rates, and quotas as configuration proposals. No checkout or payment collection in S1.
